## 1. 五分钟接通后端

### 1.1 请求地址（不要写死域名）

前端 `axios` 的 `baseURL` **留空**，用相对路径 `/api/...`：

```js
const http = axios.create({ baseURL: import.meta.env.VITE_API_BASE || '', timeout: 12000 })
```

谁来转发 `/api`：

| 跑法 | 谁转发 |
| --- | --- |
| `npm run dev`（本地开发） | Vite 的 `server.proxy` → `http://localhost:8080` |
| Nginx（`:80`，当前本机） | `/api/mall/**` → `8081`，`/api/**` → `8080` |

> 这样同一份代码在 dev 和 nginx 下都不用改。若要走电商后端，请求路径以 `/api/mall/...` 开头即可。
> 电商前端整站都调 `/api/mall/**`，所以 vite 代理要指向 **8081**。

### 1.2 统一返回体

```json
{ "code": 1, "msg": null, "data": { } }
```

- `code === 1` 成功，取 `data`
- `code === 0` 业务失败，弹 `msg`
- **成功和业务失败都是 HTTP 200**，必须判 `code`
- HTTP 401 = 没登录/token 失效

统一拦截骨架（完整版见契约文档 10.9）：

```js
http.interceptors.response.use(
  (res) => {
    const body = res.data
    if (body && typeof body.code !== 'undefined') {
      if (body.code === 1) return body.data
      notify(body.msg)
      return Promise.reject(new Error(body.msg))
    }
    return body
  },
  (err) => {
    if (err.response?.status === 401) { /* 清 token，跳登录 */ }
    return Promise.reject(err)
  }
)
```

### 1.3 鉴权：两把 token，两个请求头

| 调用方 | 请求头 | 谁签发 |
| --- | --- | --- |
| 商城买家 | `token` | `POST /api/mall/user/login` 或 `register` |
| 运营后台 | `mall-admin-token` | `POST /api/mall/admin/login` |

**两把 token 互不通用**（密钥不同）：买家 token 打后台接口 401，后台 token 打买家接口也 401。
建议单工程两端时按路由前缀自动选头（或干脆两个 axios 实例）。

### 1.4 图形验证码（登录/注册必带）

```
GET /api/mall/auth/captcha   → { key, image(PNG base64), ttlSeconds }
```

```html
<img :src="`data:image/png;base64,${image}`" />
```

- 提交时把 `key` 原样回传为 `captchaKey`，用户输的填 `captchaCode`
- **一次性**：无论对错都作废 → **登录失败后必须重新拉一张**
- 先调 `GET /api/mall/auth/policy` 拿邮箱后缀白名单 / 密码规则 / `captchaRequired`（关了就隐藏验证码控件）

## 3. 商城端：页面 → 接口

> 所有 `/api/mall/user/**` 都要带 `token`；`/api/mall/catalog/**` 和 `/api/mall/auth/**` 无需登录。

### 3.1 首页

> **字标后面的横向滚动图片墙**：`components/FlowingGallery.vue`，图池 `frontend/photo/marquee/`。
> 2 行横向跑马灯、5 张一组、无限循环（纯 CSS + 一次 ResizeObserver 量宽）。
> 层级：图片 1 → 白柔光 2 → 字标 3 → 搜索框 4 —— **图片在字标后面，不会盖住字**，也不会挡搜索框。
> 改图只需往 `photo/marquee/` 丢图（文件名随意，01、02… 控顺序；**真实格式要和扩展名一致**）。
>
> **三层动效**（参考 shop.app 的 hero 卡片）：
> ① 轨道横向无限循环 → ② 卡片 `rotateX/rotateY` **跟鼠标 3D 倾斜**（容器写 `--mx/--my`，rAF 节流）
> + `card-float` 4.4s **错峰待机浮动** → ③ 图片**反向视差**。
> 三层各管各的 transform，互不覆盖；触屏 / `prefers-reduced-motion` / `:tilt="false"` 全部退化。
> 回归：`node scripts/ui-smoke-marquee.mjs`（25 项）。
| 模块 | 接口 |
| --- | --- |
| 轮播图 | `GET /api/mall/catalog/banners?position=1` |
| 金刚区 | `GET /api/mall/catalog/banners?position=2` |
| 热销推荐 | `GET /api/mall/catalog/recommend?type=hot&limit=10` |
| 新品推荐 | `GET /api/mall/catalog/recommend?type=new&limit=10` |
| 分类导航（带商品数） | `GET /api/mall/catalog/categories` |

### 3.2 分类页 / 搜索列表
```
GET /api/mall/catalog/products/page
    ?keyword=&categoryId=&brandId=&minPrice=&maxPrice=&orderBy=&page=1&pageSize=20
```
- `orderBy` 白名单：`default | price_asc | price_desc | sales_desc | rating_desc | newest`（传错静默回落）
- **传父分类会带出后代商品**
- `GET /api/mall/catalog/brands` 给品牌筛选

### 3.3 商品详情
```
GET /api/mall/catalog/products/{id}                      商品 + 多图 + 规格 + SKU
GET /api/mall/catalog/products/{id}/review-stats          评分 / 评价数 / 好评率 / 星级分布
GET /api/mall/catalog/products/{id}/reviews?rating=&hasImage=&page=1  评价列表
```
**规格选择**：`specs[]` 是规格项，`skus[].specValues` 与 `specs` 顺序一一对应。

```js
// 例：specs=[{name:'颜色',values:['白','黑']},{name:'尺码',values:['M','L']}]
// picked = ['白','M']
const sku = skus.find(s =>
  s.specValues.length === picked.length && s.specValues.every((v, i) => v === picked[i]))
// 加购用的是 sku.id（不是商品 id）
```
- 选不中 → 该规格值置灰；下架商品详情仍能取到（`status=0`），自行决定是否禁购

### 3.4 购物车
| 操作 | 接口 |
| --- | --- |
| 列表 + 汇总 | `GET /api/mall/user/cart` |
| 角标数量 | `GET /api/mall/user/cart/count` → `{ total, invalid }` |
| 加购 | `POST /api/mall/user/cart` body `{ skuId, number }` |
| 改数量 | `PUT /api/mall/user/cart/{id}` body `{ number }` |
| 勾选单行 | `PUT /api/mall/user/cart/{id}/selected?selected=1\|0` |
| 全选/全不选 | `PUT /api/mall/user/cart/selected?selected=1\|0` |
| 删单行 | `DELETE /api/mall/user/cart/{id}` |
| 清空 / 清失效 | `DELETE /api/mall/user/cart?scope=all\|invalid` |

关键规则（决定了 UI 怎么写）：
- **价格实时**：`item.price` 是 SKU 当前价，不是加购时快照；结算金额用 `selectedAmount`
- **失效商品不消失**：`valid=false` + `invalidReason`，`selected` 对外恒为 0、不计入金额、**不能被选中**；提供「清理失效」
- `{id}` 是**购物车行 id**，不是 skuId
- 勾选失效行会报 `该商品已失效，不能选中（原因）`

### 3.5 收货地址
| 操作 | 接口 |
| --- | --- |
| 列表 | `GET /api/mall/user/address` |
| 详情 | `GET /api/mall/user/address/{id}` |
| 新增 | `POST /api/mall/user/address` |
| 修改 | `PUT /api/mall/user/address`（body 带 `id`） |
| 删除 | `DELETE /api/mall/user/address/{id}` |
| 设为默认 | `PUT /api/mall/user/address/{id}/default` |

```json
{ "consignee": "张三", "phone": "13800138000",
  "areaCode": "110101", "detail": "东华门大街 1 号", "label": "家", "isDefault": 1 }
```
- **省市区只传末级 `areaCode`**（来自 `/catalog/areas` 里 `hasChildren=false` 的节点），服务端回填省市区名称
- 三级联动：`GET /api/mall/catalog/areas`（省）→ `?parentCode=省code`（市）→ `?parentCode=市code`（区县）
- 第一条地址自动默认；设默认互斥；最多 20 条

### 3.6 下单 → 支付（**两步各一次令牌**）
```
1) GET  /api/mall/user/orders/token            → { submitToken }        （10 分钟、一次性）
2) POST /api/mall/user/orders/submit           body { addressId, remark, submitToken }
   → { id, orderNumber, totalAmount, discountAmount, freightAmount, payAmount, createTime, expireTime }
3) GET  /api/mall/user/payment/token?orderNumber=xxx  → { payToken }    （5 分钟、一次性）
4) POST /api/mall/user/payment/pay             body { orderNumber, payToken }
```
- 商品来自**购物车里「已选中」的行**，金额服务端重算，前端传不了价
- `payAmount = totalAmount - discountAmount + freightAmount`（后两者目前都是 0）
- 下单成功后服务端会**删掉已结算的购物车行**
- 令牌一次性：失败（比如购物车空）也会被消耗，**要重新取令牌**

| 操作 | 接口 |
| --- | --- |
| 分页 | `GET /api/mall/user/orders/page?status=&page=&pageSize=` |
| 详情 | `GET /api/mall/user/orders/{orderNumber}` |
| 取消 | `PUT /api/mall/user/orders/{orderNumber}/cancel`（仅待付款） |

### 3.8 评价
```
GET  /api/mall/user/reviews/order/{orderNumber}    看哪些明细已评（review=null 即未评）
POST /api/mall/user/file/upload                    晒图：单张上传（multipart file）→ URL
POST /api/mall/user/file/upload-batch              晒图：批量上传（multipart files，≤9）
POST /api/mall/user/reviews                        body { orderNumber, reviews:[{orderItemId,rating,content,images,anonymous}] }
POST /api/mall/user/reviews/{id}/follow            body { content, images }
GET  /api/mall/user/reviews/page                   我的评价
```
- 只有 **已完成** 订单能评；粒度是**订单明细**，一个明细只能评一次
- 追评只能一次，且**不改评分**
- **晒图**：先用 `/api/mall/user/file/upload` 把图传到 OSS 拿到 URL，再把 URL 数组放进 `images`（最多 9 张）

### 3.9 我的（个人中心）
| 模块 | 接口 |
| --- | --- |
| 资料 | `GET /api/mall/user/profile`（含 `avatar`，没设置过为 `null`） |
| 改资料 | `PUT /api/mall/user/profile`（可只传：`nickname` / `phone` / `avatar`） |
| **上传头像** | `POST /api/mall/user/file/avatar`（multipart 字段名 `file`，≤2MB 图片）→ 返回 OSS URL |
| 收藏列表 | `GET /api/mall/user/favorites?page=&pageSize=` |

```
① POST /api/mall/user/file/avatar   （file=图片）→ data = OSS URL（目录 supermall/avatars/{userId}/）

```

| 销售看板 | `GET /admin/stats/overview`；`/sales-trend`；`/category-sales`；`/top-products` |

**保存商品的请求体**（新增/修改共用，规格值用字符串，与详情返回同构，可「GET 详情→改→PUT 原样提交」）：

```json
{
  "categoryId": 4, "brandId": 1, "name": "纯棉圆领T恤", "subtitle": "260g 重磅纯棉",
  "detail": "100% 精梳棉…", "images": ["https://.../a.png"],
  "specs": [{ "name": "颜色", "values": ["白", "黑"] }, { "name": "尺码", "values": ["M", "L"] }],
  "skus": [
    { "skuCode": "TS-W-M", "price": 79, "stock": 100, "specValues": ["白", "M"] },
    { "skuCode": "TS-W-L", "price": 79, "stock": 120, "specValues": ["白", "L"] },
    { "skuCode": "TS-B-M", "price": 82, "stock": 90,  "specValues": ["黑", "M"] },
    { "skuCode": "TS-B-L", "price": 82, "stock": 80,  "specValues": ["黑", "L"] }
  ]
}
```
- **SKU 数必须等于各规格值数量的乘积**，否则报错并告诉你应为几个
- **无规格商品** = `specs: []` + 恰好 1 个 `specValues: []` 的 SKU
- 保存是**整体覆盖**；**想清空字段传空字符串 `""`**（传 `null` 会被当成"不改/写成 null"）

## 5. 订单状态机与按钮映射（照这个写按钮）

```
待付款 PENDING_PAYMENT ─支付→ 待发货 PENDING_DELIVERY ─发货→ 待收货 PENDING_RECEIPT ─收货→ 已完成 COMPLETED
        │                                                                                       │
        └─取消/超时(15min)→ 已取消 CANCELLED        可退款状态 ─申请→ 退款中 REFUNDING ─┬─同意→ 已退款 REFUNDED
                                                                                      └─驳回→ 回到申请前状态
```

| 订单 `status` | 买家按钮 | 后台按钮 |
| --- | --- | --- |
| `PENDING_PAYMENT` | 去支付 / 取消订单 | —— |
| `PENDING_DELIVERY` | 申请退款 | 发货（填物流公司+单号） |
| `PENDING_RECEIPT` | 查看物流 / 确认收货 / 申请退款 | —— |
| `COMPLETED` | 再次购买 / 申请退款 / 去评价 | —— |
| `REFUNDING` | 退款审核中 | 同意 / 驳回 |
| `REFUNDED` / `CANCELLED` | —— | —— |

- 退款审核驳回后订单会**回到申请前状态**，可重新申请
- 退款是**整单退款**（金额 = 订单实付）

## 6. 前端最容易踩的 15 个坑

| # | 坑 | 正确做法 |
| --- | --- | --- |
| 1 | **时间不能带秒** | 请求体里的时间要 `yyyy-MM-dd HH:mm`，带秒报「请求体格式错误或为空」；响应也是这个格式 |
| 2 | 把 HTTP 200 当成功 | 必须判 `code === 1` |
| 3 | 验证码复用 | 一次性，登录失败要重新拉；`captchaRequired=false` 时不渲染 |
| 4 | 注册完又调登录 | 注册接口**直接返回 token**，不要再登录 |
| 5 | 用商品 id 加购 | 加购要 **`skuId`**；无规格商品也有默认 SKU |
| 6 | 前端自己算订单金额 | 以服务端 `payAmount` / `selectedAmount` 为准 |
| 7 | 把失效商品藏起来 | 要展示 + 标灰 + 不能选中，金额只算有效选中行 |
| 8 | 以为 `{id}` 是商品/订单 id | 购物车 `{id}` 是**购物车行 id**；订单接口 `{orderNumber}` 是**订单号** |
| 9 | 无评价商品显示 5 分 | `reviewCount===0` 时显示「暂无评价」 |
| 10 | 收藏里看不到下架商品就报错 | 下架的也会返回（`status=0`），标灰即可 |
| 11 | 两把 token 混用 | `token`（买家）与 `mall-admin-token`（后台）不通用 |
| 12 | 支付后还想直接取消 | 已支付的只能走退款 |
| 13 | 评价晒图 / 头像直接发 base64 | 先把图传到 `/api/mall/user/file/upload`（晒图）或 `/api/mall/user/file/avatar`（头像），拿到 OSS URL 再提交 |
| 14 | **登录后无条件跟着 `redirect` 跳** | 六端会话是**按角色隔离**的（每个角色一把 token）。`redirect` 可能属于**另一个身份**（例：在 `/shop/me` 被拦下 → 到登录页后又把身份切成「商城运营」）—— 这种 redirect 再跳过去，会被路由守卫按角色拦回登录页，表现就是「提示登录成功却卡在登录页」。规则：`redirect` 是公开页或正好属于刚登录的身份才用，否则回该身份主页（实现见 `frontend/src/router/index.js` 的 `landingFor()`） |
| 15 | **富文本别指望原样存** | 商品详情是**富文本**，入库前会 XSS 清洗（白名单：`p/br/strong/em/u/ul/ol/li/h1-h4/blockquote/hr/code/pre` + `a[href]`/`img[src]`）；评价内容 / 退款说明 / 店铺简介这类**纯文本**字段会剥标签。`script`、`on*` 事件、`javascript:`/`data:` 地址不落库，站内相对图片地址（`/seed/...`）保留 |

## 9. 建议的工程结构（与外卖前端一致的模式）

```
frontend/
├── src/views/shop/**     商城用户端（首页/搜索/详情/购物车/下单/订单/评价/我的）

```
