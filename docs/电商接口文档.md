# superMall 电商板块接口文档

独立服务 **`superMall-mall`**（端口 **8081**）· 商品与物流方向 · P0~P5 + P7 已交付（P6 营销暂缓）
与外卖板块（`superMall-takeout`，端口 8080）**是两个独立进程、互不影响**，详见 [`电商板块.md`](电商板块.md)。

> 前端对接请**先读第 1 章和第 10 章**（通用约定 + 前端对接速查），再按需查具体接口。
>
> 🧭 **要写前端？先看 [`电商前端开发手册.md`](电商前端开发手册.md)** —— 按页面/流程组织，含调用顺序、状态机按钮映射、
> 常见坑与全量接口索引；本文负责逐字段的完整契约。

## 0. 基本信息

| 项 | 值 |
| --- | --- |
| Base URL（开发） | `http://localhost:8081` |
| 接口前缀 | 全部以 `/api/mall` 开头 |
| 数据格式 | JSON；文件上传用 `multipart/form-data` |
| 字符编码 | UTF-8 |
| 在线文档 | `http://localhost:8081/doc.html`（Knife4j） / `http://localhost:8081/v3/api-docs` |
| 前端代理 | 把 `/api` 代理到 `http://localhost:8081` 即可，无需处理跨域 |

依赖的中间件：MySQL（3306，**与外卖同库**）、Redis（6379，**与外卖同实例**）、OSS（与外卖同 bucket，目录不同）。

> ⚠️ Redis 版本是 **5.0.14**，服务端不会使用 6.2+ 才有的命令。

### 三类调用方

| 调用方 | 认证方式 | 典型接口 |
| --- | --- | --- |
| **游客**（未登录） | 不需要 | `/api/mall/auth/**`、`/api/mall/catalog/**` |
| **买家** | 请求头 `token` | `/api/mall/user/**` |
| **运营管理员** | 请求头 `mall-admin-token` | `/api/mall/admin/**` |

### 演示账号

| 角色 | 账号 | 密码 | 请求头 |
| --- | --- | --- | --- |
| 买家 | `user1@qq.com` / `user2@qq.com` | `Mall1234` | `token` |
| 运营管理员 | `admin@qq.com` | `Admin1234` | `mall-admin-token` |

> **买家账号与外卖完全共用**：电商注册的账号能在外卖登录，外卖登录拿到的 token 也能直接调电商买家接口
> （两边用同一把 user 密钥 + 同一个头名 `token`）。管理员是电商独有的账号体系。

## 1. 通用约定

### 1.1 统一返回体

```json
{ "code": 1, "msg": null, "data": { } }
```

| 字段 | 说明 |
| --- | --- |
| `code` | **1 成功 / 0 业务失败**。判断成败只看它 |
| `msg` | 失败时是一句可直接展示给用户的中文；成功时为 `null` |
| `data` | 业务数据；无数据的接口为 `null` |

### 1.2 认证方式

JWT 放在**请求头**里。电商板块只有两个头，**不能混用**：

| 身份 | 请求头名 | 登录接口 |
| --- | --- | --- |
| 买家 | `token` | `POST /api/mall/user/login` |
| 运营管理员 | `mall-admin-token` | `POST /api/mall/admin/login` |

```
token: eyJhbGciOiJIUzI1NiJ9.eyJyb2xlIjoiVVNFUiIsInVzZXJJZCI6MS...
```

- 买家 token 有效期 **2 小时**；管理员 token 有效期 **2 小时**
- **两个头用不同密钥签名**：买家 token 打管理员接口一定 401，反之亦然
- 登录成功后把 token 存起来，**每个请求都要带**（除了 1.1 里标「无」的公开接口）

### 1.3 HTTP 状态码

| 状态码 | 含义 |
| --- | --- |
| **200** | 请求已被业务处理。**成功与业务失败都是 200**，必须看 body 里的 `code` |
| **401** | 未登录 / token 过期 / 请求头名用错（例如买家 token 放在 `mall-admin-token` 里） |
| **404** | 路径不存在 |
| **500** | 服务端异常（body 里 `msg` 为「系统异常，请稍后再试」） |

> 收到 401 的通用处理：清掉本地 token → 跳登录页。

### 1.4 分页约定

分页接口统一用 **query 参数** `page` / `pageSize`，返回：

```json
{
  "code": 1,
  "data": {
    "total": 42,
    "records": [ ]
  }
}
```

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `page` | 1 | 页码，从 1 开始；小于 1 会被当作 1 |
| `pageSize` | 10 | 每页条数；**上限 100**，超过会被截到 100 |

> 注意：分页参数**没有默认值兜底**这件事在这里已经处理好了（不传就是 1 / 10），
> 不像外卖的 `GET /api/user/orders` 必须显式传。

### 1.5 数据格式（⚠️ 时间格式是个坑）

| 类型 | 格式 |
| --- | --- |
| 时间 | `yyyy-MM-dd HH:mm`（**不带秒**） |
| 金额 | 数字，两位小数（如 `79.00`）；**不要传字符串** |
| 布尔 | `true` / `false` |
| 长整型 id | 数字（如 `1`），**不要传字符串** |

#### ⚠️ 时间：JSON 请求体里**不能带秒**

```json
// ✅ 正确
{ "title": "双十一", "image": "https://...", "startTime": "2026-09-20 00:00", "endTime": "2026-09-21 00:00" }

// ❌ 带秒 → 报 "请求体格式错误或为空"
{ "startTime": "2026-09-20 00:00:00" }
```

> 实测：`"2026-09-20 00:00:00"` → `{"code":0,"msg":"请求体格式错误或为空"}`；
> `"2026-09-20 00:00"` → 成功。**前端提交前必须把秒去掉**（`dayjs(x).format('YYYY-MM-DD HH:mm')`）。
>
> 响应里的时间也是 `yyyy-MM-dd HH:mm`（如 `"2026-09-18 21:57"`）。

### 1.6 参数校验

请求体用 `jakarta.validation` 校验，失败时返回第一条错误信息。规则（与外卖同一套）：

| 项 | 规则 | 示例错误 |
| --- | --- | --- |
| 邮箱 `username` | 必须是邮箱，且域名在**常用邮箱后缀白名单**（40 个） | `暂不支持该邮箱后缀（qq.con），请使用常用邮箱，如 qq.com / 163.com / gmail.com` |
| 密码 `password` | 8-32 位，且同时含**大写字母 + 小写字母 + 数字**，不含空白 | `密码不达标：长度需 8-32 位、需包含大写字母（8-32 位，需同时包含大写字母、小写字母和数字）` |
| 图形验证码 | 登录 / 注册必须带 | `请先获取图形验证码` / `验证码不正确` |

规则可由 `GET /api/mall/auth/policy` 拉取，**建议前端不要写死**（见 10.3）。

## 2. 枚举

### 2.1 商品状态 `status`

| 值 | 含义 |
| --- | --- |
| `1` | 上架（前台可见、可下单） |
| `0` | 下架（前台不可见；**收藏/足迹列表里仍会返回**，需标灰） |

> 新建商品默认 `0`（先配好 SKU 再上架）。

### 2.2 通用启用状态 `status`（分类 / 品牌 / SKU）

| 值 | 含义 |
| --- | --- |
| `1` | 启用 |
| `0` | 禁用 |

### 2.3 推荐位位置 `position`

| 值 | 含义 |
| --- | --- |
| `1` | 首页轮播 |
| `2` | 首页金刚区 |
| `3` | 分类页顶部 |

### 2.4 推荐位跳转类型 `linkType`

| 值 | `linkValue` 的含义 |
| --- | --- |
| `1` | 商品 id |
| `2` | 分类 id |
| `3` | 外部链接 URL |
| `0` | 无跳转（纯展示） |

### 2.5 推荐位状态 `status`

| 值 | 含义 |
| --- | --- |
| `1` | 上线 |
| `0` | 下线 |

### 2.6 订单状态 `status`

| 值 | 含义 | 可做什么 |
| --- | --- | --- |
| `PENDING_PAYMENT` | 待付款 | 支付 / 取消 |
| `PENDING_DELIVERY` | 待发货 | 申请退款 |
| `PENDING_RECEIPT` | 待收货 | 确认收货 / 申请退款 |
| `COMPLETED` | 已完成 | 申请退款 |
| `CANCELLED` | 已取消 | — |
| `REFUNDING` | 退款中 | 等后台审核 |
| `REFUNDED` | 已退款 | — |

### 2.7 支付状态 `payStatus`

`UN_PAID` 未支付 / `PAID` 已支付 / `REFUNDED` 已退款

### 2.8 退款状态 `status`（退款单）

`PENDING` 待审核 / `APPROVED` 已同意 / `REJECTED` 已拒绝

### 2.9 退款类型 `type`

`1` 仅退款 / `2` 退货退款

### 2.10 商品排序 `orderBy`

| 值 | 含义 |
| --- | --- |
| `default`（或不传） | 后台配置的 `sort` 升序 + id 倒序 |
| `price_asc` | 按最低价升序 |
| `price_desc` | 按最低价降序 |
| `sales_desc` | 按销量降序 |
| `rating_desc` | 按评分降序（`rating` 目前固定 5.00，P5 评价系统上线后生效） |
| `newest` | 按创建时间倒序 |

> **传非法值不会报错**，会静默回落到 `default`。

### 3.5 MallSkuVO（SKU，仅详情）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | Long | **下单时传这个** |
| skuCode | String | 商家编码，可空 |
| price | Number | 该 SKU 的售价 |
| stock | Integer | 该 SKU 的库存 |
| sales | Integer | 该 SKU 的销量 |
| image | String | 规格图，可空 |
| status | Integer | 1 启用 / 0 禁用 |
| specValues | String[] | **与 `specs` 顺序一一对应**，如 `["白","M"]`；无规格商品为 `[]` |

> **如何把「用户选的规格」映射到 SKU**：用户选了白 + M → 在 `skus` 里找
> `specValues` 等于 `["白","M"]` 的那条，取它的 `id` / `price` / `stock`。
> 在 `specs[0].values` 里找不到对应值时，该规格值应置灰（没有对应 SKU）。

```

```

| 参数 | 类型 | 说明 |
| --- | --- | --- |

> 传 `minPrice=300&maxPrice=310` → 命中运动鞋（虽然它的最低价是 299）。

```

```

### 6.6 商品详情

```
GET /api/mall/catalog/products/{id}
```

返回完整 `MallProductVO`（含 `detail` / `images` / `specs` / `skus`）。

**下架商品也能取到**（`status=0`），因为收藏 / 足迹里的链接会指向它 —— 前端自行决定是否允许加购。

**带 Redis 缓存**（与外卖商品详情同款三防）：

- key `mall:product:detail:{id}`，TTL `300 + [0,120)` 秒随机抖动（防雪崩）
- 不存在的 id 会缓存空值 60 秒（防穿透），期间再请求直接返回「商品不存在」
- 缓存过期时用 `setnx` 互斥锁 + 双重检查，只放一个请求回源（防击穿）
- **后台保存 / 上下架 / 删除商品会立即删缓存**，所以运营改完买家立刻能看到
- 缓存命中期内 `stock / sales / rating / reviewCount` 可能是旧值（最长 ~7 分钟）：
  加购/下单都以 DB 为准；评分与评价数请以 `GET /catalog/products/{id}/review-stats`（不缓存）为准
- 运营后台的 `GET /api/mall/admin/products/{id}` **不吃缓存**，直查 DB

### 7.6 购物车

| 方法 | 路径 | 说明 | 返回 |
| --- | --- | --- | --- |
| GET | `/api/mall/user/cart` | 购物车列表 + 汇总 | `MallCartVO` |
| GET | `/api/mall/user/cart/count` | 角标数量 | `{ "total": 3, "invalid": 1 }` |
| POST | `/api/mall/user/cart` | 加购 | `MallCartAddVO` |
| PUT | `/api/mall/user/cart/{id}` | 改数量 | `null` |
| PUT | `/api/mall/user/cart/{id}/selected?selected=1` | 勾选 / 取消单行 | `null` |
| PUT | `/api/mall/user/cart/selected?selected=1` | 全选 / 全不选 | `null` |
| DELETE | `/api/mall/user/cart/{id}` | 删除单行（幂等） | `null` |
| DELETE | `/api/mall/user/cart?scope=invalid` | 清空（`all` 默认）/ 清理失效 | `null` |

**加购请求体**：

```json
{ "skuId": 1, "number": 2 }
```

- `skuId` 是 **SKU 的 id**（无规格商品也有默认 SKU，见商品详情）
- 同一 SKU 多次加购会**累加**，结果被库存上限截断，返回 `{ id, skuId, number }`（最终数量）
- `number` 1~999；商品下架 / 规格停用 / 售罄会被拒绝

**改数量请求体**：

```json
{ "number": 5 }
```

要点：

- **价格实时计算**：`price` 每次 JOIN `mall_sku` 取当前价，购物车不存价格快照
- **失效商品不消失**：商品下架 / 规格失效 / 售罄 / 库存不足的行照常返回，`valid=false` 并带 `invalidReason`，但：
  - 不计入 `selectedAmount` / `selectedNumber`
  - `selected` 对外恒为 `0`
  - 调勾选接口会报 `该商品已失效，不能选中（原因）`
  - 一键全选只作用于有效商品
  - `DELETE /cart?scope=invalid` 可一键清理
- **越权防护**：`userId` 从登录态取，改/删别人的购物车行 → `购物车中不存在该商品`

- 也兼容**直接传 `province / city / district`**（三者必须齐全，对应外卖侧创建的老地址）
- **第一条地址自动成为默认**；设默认会把其他地址的默认标记清掉（同一用户最多一个默认）
- 编辑默认地址时**不传 `isDefault` 也会保持默认**
- 最多 20 条地址；`userId` 由登录态注入，改别人的地址 → `收货地址不存在`
- 与外卖**共用 `address` 表**：外卖建的地址在电商也能看到、能设为默认

### 7.8 订单

| 方法 | 路径 | 说明 | 返回 |


- **商品来自购物车已选中的行**，金额由服务端重算；前端传不了价格

### 8.5 商品管理

#### 分页查询

```
GET /api/mall/admin/products/page?name=&categoryId=&brandId=&status=&keyword=&minPrice=&maxPrice=&orderBy=&page=1&pageSize=10
```

参数与前台搜索**完全一致**（见 6.5），区别是：

- 多一个 `status`（1 上架 / 0 下架 / 不传=全部）
- `name` 是「只匹配商品名」（前台的 `keyword` 匹配四个维度）；两者可同时用
- **不会强制过滤上架**

#### 商品详情

```
GET /api/mall/admin/products/{id}
```

返回完整 `MallProductVO`。**这个返回结构与「保存商品」的请求体是对称的**，
所以编辑表单可以 `GET → 改 → PUT 原样提交`，不用做 id ↔ 值 的映射。

#### 保存商品（新增 / 修改）

> ⚠️ **`detail` 是富文本，入库前会做 XSS 清洗**（Jsoup Safelist）：保留
> `p / br / strong / em / u / s / ul / ol / li / h1-h4 / blockquote / hr / code / pre` 与 `a[href]`、`img[src]`；
> `script` / `iframe` / `style`、`on*` 事件属性、`style/class/id/target`、`javascript:` / `data:` 地址一律丢弃。
> **图片地址保留相对路径与 http(s) 绝对地址** —— 演示图现在是 OSS 绝对 URL（`https://…/supermall/seed/c-001.jpg`），
> 贴站内图（`/seed/c-001.jpg`）也不会被清掉。
> 评价内容 / 追评 / 退款说明是**纯文本**，入库前只剥标签（正常文字一个字符都不动）。

```
POST /api/mall/admin/products     # 新增（dto.id 传了也会被忽略）
PUT  /api/mall/admin/products     # 修改（必须传 id）
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| id | 否 | 不传=新增 |
| categoryId | 是 | **必须是叶子分类**（有子分类的会报错） |
| brandId | 否 | |
| name | 是 | 最长 100 字符 |
| subtitle | 否 | 最长 200 字符 |
| mainImage | 否 | 不传则自动取 `images[0]` |
| detail | 否 | 详情长文本 |
| sort | 否 | 默认 0 |
| status | 否 | 1 上架 / 0 下架；**默认 0**（先配好 SKU 再上架） |
| images | 否 | 多图 URL 数组，**最多 10 张**，按顺序 |
| specs | 否 | 规格项数组，**最多 3 个**；无规格商品传 `[]` |
| skus | 是 | SKU 数组，至少 1 条 |

`specs[]` 结构：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| name | 是 | 规格名，如 `颜色`；同一商品内不重复，最长 30 字符 |
| values | 是 | 规格值数组，至少 1 个，同一规格内不重复 |

`skus[]` 结构：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| id | 否 | 修改时可带已有 SKU 的 id（当前实现是整体覆盖，传不传都会被重建） |
| skuCode | 否 | 最长 64 字符 |
| price | 是 | **必须大于 0** |
| stock | 是 | **不能为负** |
| image | 否 | |
| status | 否 | 默认 1 |
| specValues | 视情况 | **按 `specs` 顺序一一对应**的规格值；无规格商品传 `[]` |

**完整示例（2 色 × 2 码 = 4 个 SKU）**：

```json
{
  "categoryId": 4,
  "brandId": 1,
  "name": "纯棉圆领T恤",
  "subtitle": "260g 重磅纯棉，不易变形",
  "detail": "100% 精梳棉，亲肤透气。",
  "images": ["https://.../a.png", "https://.../b.png"],
  "sort": 1,
  "status": 0,
  "specs": [
    { "name": "颜色", "values": ["白", "黑"] },
    { "name": "尺码", "values": ["M", "L"] }
  ],
  "skus": [
    { "skuCode": "TS-W-M", "price": 79, "stock": 100, "specValues": ["白", "M"] },
    { "skuCode": "TS-W-L", "price": 79, "stock": 120, "specValues": ["白", "L"] },
    { "skuCode": "TS-B-M", "price": 82, "stock": 90,  "specValues": ["黑", "M"] },
    { "skuCode": "TS-B-L", "price": 82, "stock": 80,  "specValues": ["黑", "L"] }
  ]
}
```

**无规格商品**（如一瓶咖啡）：

```json
{
  "categoryId": 9,
  "name": "冷萃咖啡液",
  "specs": [],
  "skus": [{ "price": 39.9, "stock": 500, "specValues": [] }]
}
```

返回：`data` 是商品 id（新增时是新 id）。

#### ⚠️ 服务端强制的矩阵校验（都会返回明确错误）

| 场景 | 错误信息 |
| --- | --- |
| SKU 数 ≠ 各规格值数量的乘积 | `SKU 组合数不对：应等于各规格值数量的乘积（应为 4 个，实际 3 个）` |
| SKU 的 `specValues` 个数 ≠ 规格项数 | `SKU 组合数不对：…（每个 SKU 需要 2 个规格值）` |
| 规格值不在该规格的定义里 | `提交的规格值不在该商品的规格里：红` |
| 两个 SKU 规格组合重复 | `存在重复的规格组合：白` |
| 无规格商品给了多个 SKU | `无规格商品只能有 1 个 SKU` |
| 无规格商品却带了 `specValues` | `提交的规格值不在该商品的规格里` |
| 规格项 > 3 | `规格项最多 3 个` |
| 规格名重复 / 规格值重复 / 规格无值 | `规格名不能重复` / `同一规格下的规格值不能重复` / `每个规格至少要有 1 个规格值` |
| 一个 SKU 都没有 | `至少要有一个 SKU` |
| 商品挂在非叶子分类 | `商品只能挂在最后一级分类上` |
| 分类被禁用 | `分类已禁用，不能挂商品` |
| 图片超过 10 张 | `商品图片最多 10 张` |

#### 上架 / 下架

```
PUT /api/mall/admin/products/{id}/status?status=1     # 上架
PUT /api/mall/admin/products/{id}/status?status=0     # 下架
```

- `status` 只能是 1 或 0，否则 `商品状态只能是 1（上架）或 0（下架）`
- **没有任何 SKU 的商品不能上架** → `商品没有 SKU，不能上架`

#### 删除商品

```
DELETE /api/mall/admin/products/{id}
```

- **上架中的商品不能删** → `上架中的商品不能删除，请先下架`
- 删除会**连带清理**多图 / 规格项 / 规格值 / SKU / SKU 关联

- `approved=false`：退款单→`REJECTED`，订单**回退到申请前的状态**（驳回后可重新申请）
- 已审核过的退款单再审核 → `该退款申请已审核，不能重复审核`

| GET | `/api/mall/admin/reviews/page?productId=&userId=&rating=&page=&pageSize=` | 评价分页（不传过滤条件即查全部） |
| DELETE | `/api/mall/admin/reviews/{id}` | 删除违规评价 |

## 9. 调用注意事项

### 9.1 常见坑

| # | 事项 |
| --- | --- |
| 1 | **时间不能带秒** —— JSON 请求体的时间必须是 `yyyy-MM-dd HH:mm`，带秒会报「请求体格式错误或为空」 |
| 2 | **成功与业务失败都是 HTTP 200** —— 必须判断 body 的 `code === 1` |
| 3 | **验证码是一次性的** —— 登录/注册失败后必须重新获取（换 key） |
| 4 | **注册后不要再调登录** —— 注册接口已经返回 token |
| 5 | **`mainImage` 可能为 `null`** —— 前端必须占位，不要直接渲染成碎图 |
| 6 | **无规格商品也有 SKU** —— `specs` 为空数组，`skus` 是 1 条 `specValues` 为空的记录；下单时用它的 `id` |
| 7 | **下架商品仍会出现在收藏/足迹里** —— `status=0`，要标灰；但公开商品列表里看不到 |
| 8 | **公开目录的 `status` 参数无效** —— 服务端强制只看上架 |
| 9 | **非法 `orderBy` 不报错** —— 静默回落 `default` |
| 10 | **价格区间是「有交集」语义** —— 不是「最低价落在区间内」 |
| 11 | **传父分类会带出后代商品** —— 点「服饰鞋包」能查到 T恤/衬衫/运动鞋 下的商品 |
| 12 | **改商品时想清空字段要传空字符串** —— `mall_product` 的更新是**全量更新**，传 `null` 会写成 `null`、「不传」与「清空」由前端用 `""` 区分 |
| 13 | **不支持移动分类** —— 修改分类时 `parentId` 必须与原值一致 |
| 14 | **电商的 token 与外卖通用** —— 同一账号在哪边登录都行；但**管理员 token 不通用** |
| 15 | **响应时间格式** —— 也是 `yyyy-MM-dd HH:mm`（如 `2026-09-18 21:57`） |
| 16 | **购物车价格是实时的** —— `price` 来自 SKU 当前价，不是加购时快照；结算以服务端重算为准 |
| 17 | **购物车失效商品不会消失** —— `valid=false`、不计入 `selectedAmount`、不能被选中；用 `DELETE /cart?scope=invalid` 主动清 |
| 18 | **加购会被库存截断** —— 累计数量超过库存时截到库存上限，返回最终数量（不是报错） |
| 19 | **地址推荐只传 `areaCode`** —— 服务端会回填省 / 市 / 区；传省级 / 市级 code 会被拒（要选到区县） |
| 20 | **购物车/地址的 `userId` 不可传** —— 一律从登录态取，越权会报「购物车中不存在该商品」/「收货地址不存在」 |
| 21 | **下单金额服务端重算** —— 前端只传 `addressId` + `submitToken`，价格/数量以购物车和服务端 SKU 现价为准 |
| 22 | **下单令牌一次性** —— `GET /orders/token` 拿到后只能成功消费一次；失败（如购物车空）也会消耗，需重新获取 |
| 23 | **订单号是 `orderNumber` 不是 id** —— 查详情 / 取消 / 支付 / 发货都用订单号 |
| 24 | **支付后再取消要走退款** —— 已支付订单不能 `cancel`，只能 `refund` |
| 25 | **退款驳回后订单会回退** —— 回到申请前状态（待发货/待收货/已完成），可重新申请 |
| 26 | **退款是整单退款** —— 金额 = 订单实付；不支持部分退款（P5+ 可扩展） |
| 27 | **超时未支付自动取消** —— 默认 15 分钟（`super-mall.order.pay-timeout-minutes`），由定时任务每分钟扫 |
| 28 | **评价粒度是订单明细** —— 一个 `orderItemId` 只能评一次；先查 `/reviews/order/{orderNumber}` 看哪些未评（`review=null`） |
| 29 | **追评只能一次且不改评分** —— `followContent` 非空即已追评；初评图 / 追评图在返回里是两个数组 |
| 30 | **匿名评价对外固定「匿名用户」** —— 不返回昵称/邮箱；实名但无昵称时邮箱会打码成 `u***@qq.com` |
| 31 | **商品详情带 `reviewCount` / `goodRate`** —— 无评价时分别是 0 / 100.00，rating 回落到 5.00（前端用 `reviewCount===0` 显示“暂无评价”） |
| 32 | **统计口径只看已支付订单** —— `pay_status='PAID'`；未支付、已退款都不计入成交额/销量/趋势 |
| 33 | **趋势接口无成交的区间补 0** —— 日默认返回 30 个点、月 12 个；`date` 是字符串，直接当 x 轴 |
| 34 | **禁用会员不踢掉已登录 token** —— 拦截器只验 JWT；禁用后新登录会被拦，旧 token 到期前仍可用 |

### 10.3 登录页要点

1. `GET /api/mall/auth/policy` 拉规则（后缀清单 / 密码规则 / 是否需要验证码）
2. `GET /api/mall/auth/captcha` 拿 `{ key, image }`，`<img :src="'data:image/png;base64,' + image">`
3. `POST /api/mall/user/login` 传 `{ username, password, captchaKey, captchaCode }`
4. **失败后重新调 captcha 换一张**（一次性）
5. 成功后把 `token` 存起来（建议 localStorage），后续请求放请求头 `token`

### 10.4 商品详情页的规格选择

```js
// specs: [{ name:'颜色', values:['白','黑'] }, { name:'尺码', values:['M','L'] }]
// skus:  [{ id:1, price:79, stock:100, specValues:['白','M'] }, ...]

function findSku(skus, specs, picked) {         // picked = ['白','M']
  return skus.find(s =>
    s.specValues.length === picked.length &&
    s.specValues.every((v, i) => v === picked[i])
  ) || null
}

// 某个规格值是否可以选：把它和其他已选值拼起来，看有没有对应 SKU 且 stock > 0
```

- 选不中 SKU → 该规格值置灰
- 选中后用该 SKU 的 `price` / `stock` / `image`
- **加购需要 SKU 的 `id`**（不是商品 id）

### 10.7 下单 / 支付 / 退款 流程

```js
// —— 下单（两步：先取令牌，再提交）——

const order = await post('/api/mall/user/orders/submit', { addressId, remark, submitToken })
// → { orderNumber, payAmount, expireTime }

// —— 支付（Mock）——
const { payToken } = await get(`/api/mall/user/payment/token?orderNumber=${order.orderNumber}`)
await post('/api/mall/user/payment/pay', { orderNumber: order.orderNumber, payToken })

// —— 我的订单 ——
GET  /api/mall/user/orders/page?status=PENDING_PAYMENT&page=1&pageSize=10
GET  /api/mall/user/orders/{orderNumber}                 → MallOrderVO
PUT  /api/mall/user/orders/{orderNumber}/cancel          取消（仅待付款）
PUT  /api/mall/user/orders/{orderNumber}/receipt         确认收货（仅待收货）

// —— 退款 ——
POST /api/mall/user/orders/{orderNumber}/refund  { type, reason, description }
GET  /api/mall/user/orders/{orderNumber}/refund  → 退款进度（含 status / adminRemark）
```

订单状态调度建议：详情页根据 `status` 决定按钮：

| status | 买家可见按钮 |
| --- | --- |
| PENDING_PAYMENT | 去支付 / 取消订单 |
| PENDING_DELIVERY | 申请退款 / 提醒发货 |
| PENDING_RECEIPT | 查看物流 / 确认收货 / 申请退款 |
| COMPLETED | 再次购买 / 申请退款 |
| REFUNDING | 退款审核中 |
| REFUNDED / CANCELLED | —— |

> 退款审核（`GET /admin/refunds/page` + `PUT /admin/refunds/{id}/audit`）。

### 10.9 请求封装骨架

```js

  const adminToken = localStorage.getItem('mall_admin_token')

  else if (token) cfg.headers.token = token

http.interceptors.response.use(
  (res) => {
    const body = res.data
    if (body && typeof body.code !== 'undefined') {
      if (body.code === 1) return body.data
      notify(body.msg)
      return Promise.reject(new Error(body.msg))
    }
    return body
  },
  (err) => {
    if (err.response?.status === 401) {
      localStorage.removeItem('mall_token')
      localStorage.removeItem('mall_admin_token')
      router.replace('/login')
    } else {
      notify(err.response?.data?.msg || '网络异常，请稍后重试')
    }
    return Promise.reject(err)
  }
)
```
